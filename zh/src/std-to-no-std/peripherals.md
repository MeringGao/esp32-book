# 外设（Peripherals）

在继续下一部分之前，让我们快速了解一下什么是外设。

在嵌入式系统中，外设（peripheral）是扩展微控制器（MCU）功能的硬件组件。它们允许 MCU 通过处理输入和输出、通信、定时等方式与外部世界进行交互。

虽然 CPU 负责执行程序逻辑，但外设承担了与硬件交互的重活，通常将工作从 CPU 上卸载（offloading）下来。这使得 CPU 可以专注于关键任务，而外设则在很少或无需监督的情况下处理专门的功能。

## 卸载（Offloading）

卸载（offloading）指的是将某些任务委托给硬件外设，而不是直接通过 CPU 在软件中完成。这可以提高性能、降低功耗并实现并发操作。例如：

- UART 外设可以在后台使用 DMA（Direct Memory Access，直接内存访问）发送和接收数据，而 CPU 继续处理其他逻辑。
- 定时器（Timer）可以配置为生成精确的延时或周期性中断，无需 CPU 干预。
- PWM 控制器可以持续驱动电机，无需 CPU 不断地切换引脚电平。

卸载是嵌入式系统中充分利用有限处理能力的关键设计策略。

## 常见外设类型

以下是嵌入式系统中最常见的一些外设类型：

| 外设 | 描述 |
|----------|-------------|
| **GPIO** (General Purpose Input/Output，通用输入/输出) | 可配置为输入或输出的数字引脚，用于与按钮、LED 和传感器等外部硬件交互。 |
| **UART** (Universal Asynchronous Receiver/Transmitter，通用异步收发器) | 串行通信接口，用于在设备之间发送和接收数据，通常用于调试和连接蓝牙等模块。 |
| **SPI** (Serial Peripheral Interface，串行外设接口) | 高速同步通信协议，使用主从架构（master-slave architecture）将微控制器连接到 SD 卡、显示器和传感器等外设。 |
| **I2C** (Inter-Integrated Circuit，集成电路间总线) | 两线串行通信协议，用于将传感器和存储芯片等低速外设连接到微控制器。 |
| **ADC** (Analog-to-Digital Converter，模数转换器) | 将来自传感器或其他来源的模拟信号转换为微控制器可以处理的数字值。 |
| **PWM** (Pulse Width Modulation，脉宽调制) | 生成可以控制功率传输的信号，通常用于 LED 调光、电机速度控制和舵机驱动。 |
| **Timer**（定时器） | 用于生成延时、测量时间间隔、计数事件或在特定时间触发动作。 |
| **RTC** (Real-Time Clock，实时时钟) | 即使系统断电也能跟踪当前时间和日期，通常由电池供电。 |


## Rust 中的外设

在嵌入式 Rust 中，外设使用单例模式（singleton pattern）来访问。Rust 的核心目标之一是安全性，这也延伸到了它管理硬件访问的方式。为了确保程序的两个部分不会意外同时控制同一个外设，Rust 通过这种单例方法强制实现独占所有权。

### 单例模式（Singleton Pattern）
单例模式（singleton pattern）确保每个外设在整程序中只有一个实例。这避免了多个代码片段同时尝试修改同一硬件资源所导致的常见错误。

在 esp-hal 中，外设也是使用这种单例模式暴露的。但我们不会直接调用 `Peripherals::take()`。相反，我们将使用 `esp_hal::init(config)` 函数。这个函数负责基本的系统设置，并在内部为我们调用 `Peripherals::take()`。因此我们可以以安全且立即可用的形式访问所有外设。
