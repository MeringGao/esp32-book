# 为微控制器编译

现在让我们谈谈嵌入式系统。在为微控制器编译 Rust 代码时，情况与普通桌面系统有些不同。微控制器通常不运行像 Linux 或 Windows 这样的完整操作系统。相反，它们运行在一个极简的环境中，通常根本没有操作系统。这被称为裸机（bare-metal）环境。

Rust 通过其 **no_std** 模式支持这种设置。在普通的 Rust 程序中，标准库（`std`）负责处理文件系统、线程、堆分配和 I/O 等事务。但在裸机微控制器上，这些都不存在。所以我们不用 std，而是使用一个更小的 `core` 库，它只提供最基本的构建模块。

## ESP32 与 `std`

这里有一个有趣的地方：ESP32 实际上是可以运行 `std` 的，但前提是你使用官方的 ESP-IDF 框架。ESP-IDF 提供了类似操作系统的功能。这使得在 ESP32 上使用基于 std 的 Rust 代码成为可能。

在本书中，我们不会使用 `std`。我们将完全专注于使用 `no_std` 的裸机（bare-metal）方法。

## ESP32 的目标三元组

要为微控制器编译 Rust 代码，我们需要指定一个自定义目标。对于 ESP32 的裸机开发，目标三元组如下所示：

```sh
xtensa-esp32-none-elf
```

让我们来分解一下：

- **架构（xtensa）**：ESP32 基于 Xtensa 架构，而不是 ARM 或 x86。
- **厂商（esp32）**：指 Espressif 的特定芯片系列。
- **操作系统（none）**：这告诉 Rust 我们没有使用操作系统——这是裸机。
- **格式（elf）**：这第四部分很重要。在许多目标中，第四项是 ABI（如 `gnu` 或 `msvc`）。但在这里，它不是 ABI——而是目标文件格式。它将是 ELF（Executable and Linkable Format），这在嵌入式系统中很常见。


等一下……你可能会想：我们从来没有对 ESP32 使用过 "rustup target add" 命令！那是因为 espup 工具已经帮我们处理好了。我们在开发环境部分已经设置过了。事实上，你无法使用常规的 rustup target 命令直接添加 ESP32 目标。相反，espup 会安装一个名为 "esp"（或你选择的任何自定义名称）的独立 Rust 工具链，而该工具链已经内置了对 ESP32 目标的支持。


## Cargo 配置

在快速入门中，你可能已经注意到，我们运行 cargo 命令时从未手动传递过 --target 标志。那么它是怎么知道要为哪个目标构建的呢？那是因为目标已经在 .cargo/config.toml 文件中配置好了。

这个文件允许你存储与 cargo 相关的设置，包括默认使用哪个目标。要为 ESP32 进行设置，请在项目根目录下创建一个 .cargo 文件夹，并添加一个包含以下内容的 config.toml 文件：

```toml
[build]
target = "xtensa-esp32-none-elf"
```

现在你不需要每次都传递 --target 了。Cargo 会自动使用这个配置。
