# 将 ESP32 Web 服务器暴露到互联网

通常不建议在没有适当安全措施的情况下从互联网访问 ESP32 等托管的物联网（IoT）Web 服务器。这些设备容易受到攻击，例如未经授权的访问、被纳入僵尸网络，或根据设备类型造成其他损害（我不会冒这个风险）。此外，由于端口暴露、处理流量负载和潜在的安全风险等挑战，使用 ESP32 作为 Web 托管服务器并不实际。也就是说，如果您想尝试一下或向朋友展示，它可以是一个很好的学习体验。

## 路由器端口转发

一种选择是在路由器上设置端口转发，将外部 IP 和端口（例如，公网 IP 202.xx.xx.10）映射到 ESP32 的私有 IP 和端口（例如，192.168.56.101）。然而，大多数家庭网络使用 ISP 分配的动态公网 IP 地址，这可能会随时间变化。这会使设置不可靠，并且在某些情况下可能无法工作。为了确保一致的访问，您可能需要配置静态公网 IP 地址，这通常需要联系您的 ISP，并且可能会产生额外费用。

您还可以将 No-IP 等服务与端口转发一起使用，并且可以使用动态 IP 地址。如果您的路由器支持，您可以在路由器设置中直接配置 DDNS 或 No-IP。您可以在 No-IP 官方网站 [此处](https://www.noip.com/integrate/request) 找到更多详细信息。但是，请记住，这种方法可能不适用于某些在动态 IP 地址上阻止开放端口的 ISP。

## 隧道（Tunneling）

在隧道选项中，您不需要静态 IP 地址，但您需要使用提供隧道的外部服务。为了使其工作，您必须在您的 PC 或 Raspberry Pi（不是 Pico）上安装客户端并运行客户端以建立隧道（我知道，这不好玩）。您不能在 ESP32 上运行此客户端。隧道设置完成后，您可以使用提供商生成的 URL 访问服务器。

您可以使用 ngrok 或 Cloudflare Tunnel 等服务。要开始使用 ngrok，您可以查看官方指南 [此处](https://ngrok.com/docs/getting-started/?os=linux)。对于 Cloudflare Tunnel，官方指南可在 [此处](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) 获取。

### ngrok 示例

例如，使用 ngrok 时，我首先在他们的门户网站上注册并获得了身份验证令牌。之后，我在计算机上运行客户端并使用命令 `ngrok config add-authtoken MY_AUTH_TOKEN` 添加了令牌。

为了建立隧道，我运行了以下命令：`ngrok http 192.168.0.101:80`。这里，192.168.0.101 是 ESP32 的 IP 地址。客户端然后在 ngrok 域下生成了一个公共 URL。我能够从不同的网络（例如：手机网络）访问此 URL 以确认隧道正常工作。
